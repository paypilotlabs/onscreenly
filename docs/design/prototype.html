When this window opens

macOS
The system asks for the microphone, then screen recording. If either is still off, this window is the welcome screen, and Continue waits for both.
Windows
No window on first run: onboarding step 2 asks instead. A returning user with the microphone off sees it above the overlay, with “Continue without microphone”.
Linux
Never shown. Linux doesn’t ask for these permissions.

“Check again” inside the window steps through not requested, microphone allowed, then both.

    What changes vs today

      Each control sets one state on the live prototype, through the same calls the scenes use. Answer and error states replace the answers on screen.

      These replay the app’s own system-setting rules on both windows, as if the operating system asked for them.

      Keyboard

      • Tab moves through the stage; dialogs keep focus inside.
      • Esc closes one layer per press: consent, onboarding, Settings, composer text, popover, sidebar.
      • ← → move between Settings tabs.
      • ⌘⇧L Start or end a session.
      • ⌘↵ What should I say? · ⌘⇧↵ Assist

      Design system

      Tokens

      The Cluely token set, read from this page’s own stylesheet, then the type steps and the two semantic themes built on it.

      WCAG 2.2

      Contrast

      Computed live from the rendered colours. Text needs 4.5:1; control marks (carets, checkbox edges), focus rings and large text need 3:1. It follows the opacity slider and the accessibility toggles.

      Shared controls

      Components

      Every shared control in both themes, with hover, pressed and focus forced on. They use the production rules; only Send is a look-alike, because the app styles it by id.

      Settled

      Decisions

      All 14 approval items at their defaults, plus two decisions from the review: no icons, and ⌘⇧L for the session.
